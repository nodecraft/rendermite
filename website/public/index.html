Stone

Built to match the game

rendermite reads the same models, textures and transforms the client does, then draws the icon the way the inventory draws it.

  • Inventory-identical

    Orthographic block projection, per-face GUI lighting, display transforms, tints, enchant glint, and animated textures as animated WebP.

  • Every version

    Era detection, donor geometry and legacy spritesheet slicing for old releases. Item definitions, atlases, armor trims and decorated pots for new ones.

  • Real mod support

    Forge, NeoForge and Fabric loader models, OBJ and MTL meshes, GeckoLib Bedrock geometry, cross-jar dependencies, and the malformed JSON mods ship anyway.

  • No black squares

    Items the game draws in code fall back through block models, builtin geometry and flat sprites. Anything still unrenderable is written to a failures file with a reason.

  • Small, drop-in output

    Palette PNG only when it is lossless, lossless WebP, and a minified stylesheet that follows renderchest's class names, so existing markup keeps working.

  • Block packs too

    Geometry, atlases, blockstates, tints, biomes and entity models exported as pre-resolved JSON, for renderers that draw the world themselves.

Hosted icons, free of charge

Nodecraft renders every release and thousands of mods with rendermite and publishes the output to assets.rendermite.dev. Link the stylesheet and use the classes, or point an <img> at a single icon.

About the artwork

We don't own any of these icons. Each one is drawn from textures and models that belong to Mojang or to the authors of each mod, and every right in that artwork stays with them. We host the renders free of charge as a convenience, with no ads, accounts or fees, and we don't sell them or offer any license to them. rendermite's MIT license covers its code only.

If you made a mod and want its icons changed or taken down, open an issue and we will handle it.

URL layout

Path on assets.rendermite.dev What it is Cache
/versions.json Every published version, newest first 5 min
/icons/version/rc-minecraft-64.css Stylesheet with a class per item, glint and tint support Immutable
/icons/version/items/minecraft/item.webp One icon, 64px lossless WebP, animated where the item animates. .png also available. Immutable
/icons/version/items-version.json Item registry: id, display name, stack size Immutable
/icons/version/rc-minecraft-failures.json Items that did not render, each with a reason Immutable
/icons/modded/namespaces.json Every mod namespace on the CDN Updated as mods are added
/icons/modded/css/namespace.css Stylesheet for one mod 1 hour
/icons/modded/items/namespace/item.webp One modded icon 30 days
/blocks/versions.json Published block packs; each lives under /blocks/version/ 5 min

Everything under /icons/version/ is immutable: a re-render gets a new path, so cache it for as long as you like.

Deep dark

Render your own

Point rendermite at a version and it downloads and caches the client jar. Add mod jars, a resource pack, or an extracted asset tree.

Terminal 
rendermite --version 1.21.8 --output ./icons

rendermite --version 1.20.4 \
  --mod ./create-1.20.1.jar \
  --namespace create \
  --output ./icons/create --item-list
render.ts 
import { prepareVersionResources, run } from '@nodecraft/rendermite';

const resources = await prepareVersionResources({
  version: '1.21.8',
  jar: './1.21.8-client.jar',
});
const result = await run({ resources, output: './icons', itemList: true });

console.log(`${result.rendered.length} rendered, ${result.failed.length} failed`);
